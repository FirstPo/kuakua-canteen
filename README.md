# 夸夸食堂

一个只给两个人用的微信小程序：她点菜，必须先写一段夸奖；系统按固定规则打 0–100 分，达到你设定的满意线才准付款；你确认收到转账后开火、出锅。

不是外卖，是把「先夸后吃」做成一个能留档、能打回、有点好笑的两人仪式。

这份仓库是通用模板：**每个人用自己的小程序 AppID 和云开发环境，数据互不相通**。想给朋友用，把整个目录打包发给他，让他照下面的「换成你自己的小程序」做一遍。

## 两种跑法

| | mock | cloud |
|---|---|---|
| 需要 AppID | 不需要 | 正式注册的小程序 AppID |
| 数据在哪 | 本机微信存储 | 微信云开发数据库 |
| 适合 | 先玩一遍、看界面 | 两个人各自手机真同步 |

默认配置是 `MODE: 'mock'`，导入开发者工具就能玩。要两个人真用，走云开发。

## 五分钟先玩起来（mock，不需要 AppID）

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 打开开发者工具 → 导入项目 → 选择本目录。
3. AppID 选「测试号」或当前登录账号的 AppID；mock 模式不校验 AppID，点导入。
4. 编译。首次进入会看到开张页：
   - 选「我是厨师」或「我是食客」，填称呼和 emoji。
   - 选完一方后，mock 会自动补上另一方的默认账号，方便你在一台手机上切角色。
5. 在「我的 → 演示模式」里可以：
   - 切换当前身份；
   - 载入演示数据（一条已出餐的高分订单 + 一条被打回的翻车记录）；
   - 清空演示数据，重新开张。
6. 食客流程：食堂点菜（菜单没有就自己加一道）→ 写夸奖 → 开分 → 过线后去付款 → 我已转账。
7. 厨师流程：厨房 → 确认收款 → 开火 → 出锅；也可以打回已过线的夸奖或破格准了。

mock 数据只存在这台设备的微信本地存储里，**不是双人同步方案**。两个人各自手机用，必须走下面的云开发。

## 换成你自己的小程序（cloud）

### 0. 你需要准备

- 一个**正式注册**的小程序 AppID。微信「接口测试号」不支持云开发，这是硬限制。
- 微信开发者工具，并已用你的微信登录。
- 云开发环境（在开发者工具里开通，未发布的小程序通常有免费体验环境，以控制台为准）。

### 1. 导入并开通云开发

开发者工具 → 导入项目 → AppID 填你自己的 → 打开「云开发」→ 开通 → 创建环境，记下环境 ID（形如 `cloud1-xxxxxxxx`）。

### 2. 写入 AppID 和环境 ID

在项目根目录执行：

```bash
node scripts/configure.js --appid wx你的AppID --env 你的环境ID
```

它会同时改好 `project.config.json` 和 `miniprogram/config.js`。核对：

```bash
node scripts/configure.js --show
```

不想用命令，也可以手动改这两个文件：`project.config.json` 的 `appid`，以及 `miniprogram/config.js` 的 `MODE: 'cloud'` 和 `CLOUD_ENV_ID`。

### 3. 部署云函数

右键 `cloudfunctions/api` → **上传并部署：云端安装依赖**。`wx-server-sdk` 已固定在 `4.0.2`，不需要本地 `npm install`。

确认云函数状态是 `Active`。首次部署可能提示「当前函数处于 Creating 状态」，等十几秒重试即可。

### 4. 首次启动

重新编译小程序。首屏的 `bootstrap` 会自动：

- 建 `users` / `settings` / `dishes` / `orders` 四个集合；
- 灌入 10 道陕西家常示例菜；
- 返回当前角色和食堂设置。

看到「开张」页、两张身份卡，就说明云开发通了。

四个集合的权限建议在云开发控制台设为 **「仅管理端可读写」**。客户端只调用云函数，不直接碰数据库。

### 5. 两个人绑定

- 厨师先进入，选「我是厨师」，设昵称、满意线、最低字数。
- 另一个人进入，选「我是食客」。
- 第三个人进入会看到「本食堂只接待两位贵客」。

角色在 App 内不能重置。要重来，见下面的「重置」。

### 6. 体验版

1. 开发者工具点「上传」，填版本号。
2. 小程序后台 → 版本管理 → 把开发版本设为体验版。
3. 成员管理 → 体验成员，把对方的微信号加进去。
4. 版本管理 → 体验版 → 下载二维码，发给她。二维码一般 7 天有效，过期重下。

### 常见问题

- **`env ... not exists`**：环境 ID 写错了，用 `--show` 核对，或在控制台重新复制。
- **`ResourceUnavailable.ResourceExist / Table exist`**：集合已存在，代码会当幂等跳过；仍报错就去控制台手动建四个集合。
- **首屏「后厨出了点问题」**：看云函数日志里的 `[api] action=bootstrap`；确认云函数已部署最新代码。
- **云函数超时**：默认 3 秒，首次初始化已改成并发写入；仍超时就在控制台把超时调到 10–20 秒。
- **测试号开不了云开发**：必须正式注册小程序。
- **二维码打不开**：先加体验成员，再重新下载二维码。

更多排障和智能体交接说明见 [`AGENTS.md`](AGENTS.md)。

## 规则

- 一单可以点 1–20 道菜，单道最多 20 份，价格由服务端按数据库现价重算并快照。
- 菜单上没有的菜可以自主添加：填菜名、想怎么吃、图标，价格 1–999 元由她先出；下单时快照，厨师不认可以打回整单。和菜单同名会被拒绝，避免绕过菜单价。
- 含自点菜的订单门槛加严：满意线 +8 分、最低有效字数 +10（默认 88 分、30 字），满意线最高 100、最低字数最高 60。加严后的门槛会写进订单和每一轮夸奖。
- 每次提交都带一轮夸奖。五项打分：篇幅 25、具体 25、走心 25、新意 15、表达 10。
- 硬伤（有效字数不足、和历史夸奖高度重复、复读/刷屏、纯表情、标点灌水）会把总分封顶在 49。
- 默认满意线 80 分、最低有效字数 20。厨师可以在「我的」里调（满意线 60–100，最低字数 10–50）。
- 过线后厨师仍可以打回；没过线厨师也可以破格通过。
- 订单状态：`rejected → approved → payment_claimed → paid → cooking → served`，另有 `cancelled`。
- 同一时间只允许一张进行中的订单（`rejected` 到 `cooking`）。
- 歇业只拦新单，进行中的订单可以继续重夸和走完流程。

## 支付说明

个人主体小程序不能开通标准微信支付，所以这里是：

1. 她的夸奖过线 → 页面显示菜钱和「复制收款信息」。
2. 她微信转账给你，回来点「我已转账」，可填转账备注。
3. 你核对到账，点「确认收款」。
4. 你点「开火」「出锅」。

所有金额用整数分存储。没有自动扣款、退款或对账接口。

## 常用命令

```bash
npm test
```

跑 48 个 Node 测试：打分校准、硬伤、完整订单生命周期、自点菜加严门槛与价格快照、购物车迁移、并发幂等、角色/状态守卫、mock 本地存储、页面脚本集成（模拟 `wx` / `Page` 环境），以及共享模块一致性。

```bash
npm run validate
```

静态校验：JSON、页面四件套、组件引用、自定义 tabBar、云函数文件、JS 语法、共享模块同步、WXML 事件方法是否存在。

```bash
npm run configure -- --show
```

查看当前的 AppID / 云环境 / 运行模式；改配置用 `--appid`、`--env`、`--mock`。

```bash
npm run sync
```

改了 `shared/` 之后同步到 `miniprogram/shared/` 和 `cloudfunctions/api/lib/`。`npm test` 会自动先执行。

```bash
npm run sync:check
```

只检查两份拷贝是否逐字节一致。

## 重置

### mock

「我的 → 演示模式 → 清空演示」，会清空本机所有身份、菜品和订单，回到开张页。

### 云端

在云开发控制台：

- 删除 `users` 和 `settings` 集合里的所有记录；`settings` 里存着两个角色槽位，删掉后可以重新选身份。
- 如需彻底重来，再删 `orders`、`dishes`，首次启动会重新灌示例菜。
- 或者直接删掉云环境、重建一个新的。

## 限制与注意

- 打分是确定性规则，不是 AI。它服务于「好玩和门槛」，不是安全边界；厨师的人工否决权才是最终裁决。
- 自点菜是「点菜请求」，不会自动进菜单，也没有单独议价流程；价格由她先出，你不同意就打回整单。想长期卖这道菜，还是去厨房里正式上架。
- 不调用微信头像/昵称授权，昵称和 emoji 手动设置。
- 没有订阅消息/推送；新单靠打开小程序或下拉刷新。
- 菜品用 emoji，不接图片上传；个别安卓机型 emoji 样式会不同。
- 不公开发布：公开发布会涉及备案、类目审核、UGC 内容安全检测，不在本期范围。
- 云开发的免费额度/体验环境和计费规则以控制台为准；正式长期使用可能产生费用。
- 项目里的 `project.private.config.json` 和 `node_modules` 已被 `.gitignore` 忽略。
